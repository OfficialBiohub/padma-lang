# Changelog

All notable user-visible changes are recorded in this file. Padma follows a pre-1.0 development policy: interfaces may evolve, but breaking changes require a migration note and explicit review.

## Unreleased

### Added

| Area | Change |
|---|---|
| Repository | Language-first repository architecture, documentation index, examples/tooling/test indexes, collaboration policies, issue forms, pull-request template, and repeatable quality scripts. |
| Agent engineering | Versioned `padma-language` Agent Skill with modular architecture, security, Termux, examples, and verification guidance. |
| M9 design | Provider-neutral AI workflow and domain-allowlisted browser-planning contract, including capability boundaries, manifest schemas, redaction, no-side-effect plans, regression matrix, and staged implementation order. No new AI or browser runtime authority is enabled by this documentation change. |
| M9 AI planning | Strict `padma-ai.toml` validation, `network:ai`-gated `padma ai inspect|plan`, bilingual `P1050`, redacted deterministic plans, and a credential-free example. These local commands do not read secrets, resolve DNS, start a process, connect to a provider, invoke a model, or execute generated output. |
| M9 AI runtime | Provider-neutral `ai.workflow` with an inert JSON input/output envelope, one `json-http-v1` curl configuration path, fixed POST request, no redirect/retry, bounded timeout/output, and bilingual `P1051`/`P1052` transport diagnostics. A test-only local mock proves one transport invocation without a network request. Model output remains data and is never executed. |
| M9 browser planning | Strict `padma-browser.toml` validation, `browser:plan`-gated `padma browser inspect|plan`, bilingual `P1053`–`P1055`, exact HTTPS-origin and simple navigation-path enforcement, deterministic read-only plans, security-negative regression tests, and a credential-free example. These commands do not start a browser, resolve DNS, connect to a network, read cookies/credentials/environment values, start a process, or navigate to a URL. |
| M10 AI tool planning | Strict `padma-ai-tools.toml` validation, `ai:tools`-gated `padma ai tools inspect|plan`, required underlying capability checks, bilingual `P1056`/`P1057`, deterministic bounded runbook descriptors, security-negative regression tests, and a credential-free example. These commands do not invoke a tool, start an agent, read a secret/environment value, connect to a network, start a process, write an audit log, or execute generated output. |
| M10 AI training planning | Strict `padma-ai-training.toml` validation, `ai:training-plan`-gated `padma ai training inspect|plan`, bilingual `P1058`/`P1059`, project-relative dataset/artifact metadata, resource ceilings, security-negative regression tests, and a credential-free example. These commands do not read a dataset, write an artifact, start a training backend/process, use remote compute, read environment values, connect to a network, or execute generated output. |
| M10 browser action design | Confirmation-gated `browser:navigate` design contract with exact-origin plan binding, destination revalidation, redirect denial, isolated-session policy, cancellation, redacted audit requirements, and a security-negative test matrix. This is design documentation only; no browser action capability or runner has been added. |
| M10 browser confirmation planning | Strict `padma-browser-confirm.toml` validation, `browser:confirm-plan`-gated `padma browser confirm inspect|plan`, browser-plan digest/index binding, bilingual `P1060`/`P1061`, deterministic awaiting-confirmation descriptors, security-negative regression tests, and a credential-free example. These commands do not issue a confirmation, start a browser, resolve DNS, connect to a network, read cookies/credentials/profile/environment values, execute JavaScript, submit a form, post, pay, upload, download, or invoke an action runner. |
| M10 Android Browser Handoff | `browser:handoff`-gated `padma browser handoff`, foreground `OPEN` confirmation, exact confirmation-plan digest binding, and one shell-free `termux-open-url` invocation with exactly one reviewed HTTPS URL. Bilingual `P1062`/`P1063`, negative security tests, a Termux example, and failure-safe behavior are included. Padma does not control the Android browser, read/export its profile/cookies/credentials, pass headers/scripts/selectors, log in, bypass CAPTCHA, submit forms, post, upload/download, change accounts, purchase, or pay. |
| M10 Browser Handoff hardening | Explicit pre-handoff cancellation, opt-in `browser:audit` local audit capability, strict `padma-browser-audit.toml`, fixed-field redacted JSONL retention, bounded record/file policy, symlink/path-traversal/record-shape rejection, atomic local replacement, and bilingual `P1064`. The audit never writes a raw URL/query, terminal approval text, browser profile/cookie/credential/header, page content, browser output, or generic error content. |
| M11 browser interaction drafts | Strict `padma-browser-draft.toml`, `browser:draft`-gated `padma browser draft inspect|plan`, digest/index binding to one reviewed URL, bounded local text, attachment metadata only, bilingual `P1065`/`P1066`, a safe Termux example, and security-negative regression tests. Draft commands do not start a browser, resolve DNS, connect to a network, read an attachment, fill/submit a form, post, upload/download, access credentials/cookies/profiles, inject JavaScript, or execute generated output; login, CAPTCHA, and every sensitive action require visible user takeover. |
| M12 visible browser takeover | Strict `padma-browser-takeover.toml`, `browser:takeover`-gated `padma browser takeover inspect|plan`, digest/index binding, fixed sensitive-action labels, bilingual `P1067`/`P1068`, a safe Termux example, and security-negative regression tests. The checklist creates no approval or action authority: it does not launch/control a browser, access credentials/cookies/profiles/page state, fill/submit/post/upload/download, change accounts, purchase/pay, inject scripts, execute output, or record user completion. |
| M13.1 structured data toolkit | Capability-gated local `table.read`, `table.headers`, `table.rows`, `table.filter_equal`, `table.select`, `table.count_by`, and `table.write_csv` for bounded CSV/TSV/object-row JSON tables, bilingual `P1069`, safe inventory example, and project-root/security-negative regression tests. No Excel/XLSX, cloud sync, shared-storage access, macro execution, or network behavior is added. |
| M13.2 filesystem productivity | Project-only `fs.list`, `fs.checksum`, `fs.search_text`, and `fs.copy_plan`/`fs.move_plan`/`fs.archive_plan` with bounded non-symlink source inspection, deterministic disabled plan descriptors, bilingual `P1070`, a safe Termux example, and project-root/security-negative regression tests. No file mutation, shell/process invocation, background daemon, Android shared storage, archive backend, or network behavior is added. |
| M15.1 local reporting | `report.markdown`, `report.summary`, and capability-gated `report.write_markdown` for escaped deterministic Markdown reports from validated tables, bilingual `P1071`, a safe expense-report example, and export/path/title/symlink/injection security tests. No cloud/email/upload/share, HTML/script execution, payment/invoice action, background job, shared storage, or public publishing is added. |
| M16 simple project starter | `padma init` now creates the beginner-friendly `src/`, `data/`, `out/`, `tests/`, and `README.md` layout with a minimal no-capability manifest and clearer next commands. Existing flat projects and direct `padma file.pd` execution remain compatible; non-empty, traversal, and symlink targets are rejected. |
| Quality | Repository hygiene, documentation-link, and Termux installer-contract checks integrated with CI. |
